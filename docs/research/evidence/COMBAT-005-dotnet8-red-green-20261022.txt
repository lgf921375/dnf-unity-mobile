CHECKS / KNOWN LIMITATIONS
- These console checks compile actual .NET C# reference classes, but the UnityEngine definitions in
  Runner.cs are TEST-ONLY stand-ins; not real SpriteRenderer, Unity Editor, PlayMode, Android or cloud build.
- "Interval hit-window traversed" records TIMING eligibility. It does not assert physical collision,
  hitbox swept intersection, damage, per-target contact dedup, or hitstop implementation.
- Current clock is a simplified three-stage sample, not a full DNF/Dawnbreak combat simulator.
- Current input buffer (0.16 seconds) is an EXPERIMENTAL value and not a verified official DNF value.
- Additional edge cases not proven by these tests: single-precision ULP neighbors at all boundaries,
  overlapping multiple attack events in one large dt, sprite crop/PPU/parent negative scale,
  flipX toggled without reapplying alignment.
- Recommended future per-target dedup key in combat layer: (attackInstanceId, targetId, hitIndex),
  or add stage identity to the attack-instance key if reused.
- Hitstop contract to decide in separate authorized task: freeze attacker's and victim's combat-local
  action/animation/physics clock on accepted collision; keep UI/network clock running; decide whether
  buffering continues during freeze but decay uses combat-local time; test deterministic time axes.
- Another accepted limitation: a clock that advances past a stage transition does not retain a
  chronological per-stage hit-event queue; future combat collision system must scan swept intervals
  at runtime rather than treating the clock's latest candidate as a resolved hit.
